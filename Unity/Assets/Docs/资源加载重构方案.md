# 资源加载重构方案

## 目标

- 提供统一资源入口，屏蔽 `YooAsset / Resources / Addressables` 差异。
- 支持 `TextAsset / TileBase / Sprite / Prefab / AudioClip / Scene`。
- 支持异步加载、重试、分组预热、缓存与引用释放。

## 业务迁移状态

- 地图链路已接入统一门面：
  - `TilemapManager`：初始化并使用 `AssetService`，支持通过 key 加载 `TileDatabase`。
  - `ChunkTemplateLoader`：改为通过 `LoadTextAssetsByGroupAsync` 读取模板文本，不再直接 `Resources.LoadAll`。
- 旧 `IResourceProvider/ResourcesProvider` 保留兼容，但已转调新资源门面。

## 运行时说明

- 若场景中挂载 `AssetRuntimeBootstrap`，会在早期初始化并注册 `AssetService`。
- 若未挂载，`TilemapManager` 也会兜底初始化一个默认 `AssetService`。
- `YooAssetBackend` 与 `AddressablesBackend` 当前为反射兼容版本（未安装包时不会编译报错，自动回退到可用后端）。

## 下一步建议

1. 创建 `AssetRoutingConfig` / `AssetGroupsConfig` 实例并在启动场景挂载 `AssetRuntimeBootstrap`。
2. 将核心资源 key 化并写入分组配置。
3. 在接入真实 YooAsset 包后，将 `YooAssetBackend` 从反射模式替换为强类型 API。
