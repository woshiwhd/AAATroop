# 资源命名与分组规范（微信小游戏向）

本文档定义项目资源命名、分组和版本标识规则，用于降低后续接入 `YooAsset` 的迁移成本。

## 1. 命名目标

- 看名字即可判断用途、模块、资源类型
- 支持批量打标签（Tag/Label）
- 减少多人协作时命名冲突
- 为分包、热更、回滚提供稳定键名

## 2. 分组前缀规范

统一使用四类前缀：

- `base_`：首包必须资源
- `feature_`：玩法模块资源
- `event_`：活动资源
- `audio_`：音频资源

示例：

- `base_core`
- `base_map`
- `feature_combat`
- `event_spring2026`
- `audio_bgm_main`

## 3. 资源键（Address/Key）命名格式

推荐格式：

`<prefix>_<module>_<assetType>_<name>[_vN]`

建议全部使用小写 + 下划线，不使用空格。

示例：

- `base_map_tile_grass_01`
- `base_map_tile_grass_08`
- `feature_combat_fx_hit_small`
- `event_spring2026_ui_banner_main`
- `audio_bgm_main_town_v2`

## 4. 目录组织建议

目录可按模块存放，但分组与命名遵循统一规则：

- `Assets/.../base_*`
- `Assets/.../feature_*`
- `Assets/.../event_*`
- `Assets/.../audio_*`

说明：目录结构可调整，但 Address 与分组命名尽量保持稳定，避免线上资源键频繁变更。

## 5. 当前项目特别约束

### 5.1 TileDatabase id 规则

`TileDatabase` 的 id 从 1 开始：

- `id = 0` 表示空
- `id > 0` 映射到 `tiles[idx]`，其中 `idx = id - 1`

参考：`Assets/Script/Utilities/TileDatabase.cs`

### 5.2 草地变体规则

`ProceduralChunkGenerator` 当前按连续 id 选草地变体：

- 起点：`baseTileId`
- 数量：`grassVariantCount`
- 结果范围：`baseTileId .. baseTileId + grassVariantCount - 1`

参考：`Assets/Script/Managers/ProceduralChunkGenerator.cs`

## 6. 禁止项（红线）

- 禁止中英文混合随意命名（统一小写英文 + 下划线）
- 禁止在 `base_` 中放非首屏必需资源
- 禁止复用旧活动前缀覆盖新活动内容（活动资源使用独立 `event_xxx`）
- 禁止无版本标识地直接覆盖高风险核心资源（必要时加 `_vN`）

## 7. 维护流程建议

1. 新增资源前先确定所属前缀（base/feature/event/audio）
2. 按格式命名 Address/Key
3. 合入前执行一次命名检查（人工或脚本）
4. 版本发布时记录分组变更清单，便于回滚
