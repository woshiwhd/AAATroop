# Minecraft 式程序化随机地图设计文档

本文档描述如何在现有 Chunk + 模板管线之上实现「我的世界式」随机地图：**随玩家视野移动按需生成**前方地形与建筑，支持无限延展，且同一局内同一 chunk 再进入时**确定性一致**。符合 2D 游戏逻辑：视野驱动、按需生成、种子可复现。

---

## 一、目标与约束

### 1.1 目标

- **按需生成**：仅在 chunk 进入玩家视野时生成该 chunk，不预生成整张地图。
- **确定性**：同一局游戏、同一 chunk 坐标 `(cx, cy)`，多次进入得到相同的地块内容（种子 + 坐标决定）。
- **无限/流式**：世界理论上无限大，玩家走到哪就生成到哪。
- **兼容**：不破坏现有「ChunkManager 按视野算 desired → TilemapManager 按 desired 加载」管线；可保留「无程序化时随机模板回退」行为。

### 1.2 与「暗黑式」的区别

| 对比项 | 暗黑式（房间+走廊） | Minecraft 式（本设计） |
|--------|---------------------|------------------------|
| 生成时机 | 进入关卡时一次性生成整张布局 | 按需：chunk 进入视野时才生成 |
| 数据结构 | 预先生成布局表（房间/走廊） | 无预布局，每个 chunk 独立用噪声/规则生成 |
| 地形 | 模板拼装 | 噪声（Perlin/Simplex）+ 规则 或 模板+噪声混合 |
| 建筑 | 布局中指定 | 噪声或规则决定「此处是否放建筑模板」 |
| 典型玩法 | 地牢、关卡 | 开放世界、沙盒、横版/俯视角探索 |

### 1.3 当前管线（简要）

- **ChunkManager**：按相机视野计算 `desired` chunks，调用 `TilemapManager.SetDesiredChunks(desired)`。
- **TilemapManager**：对每个未加载的 chunk 调用 `LoadChunkInternal`；当前实现里若开启 `useTemplateFallback`，会用 `ChunkTemplateLoader.GetRandomTemplateCopy()` 取随机模板填充（随机、无种子、同一 chunk 再进入可能不一致）。**目标形态**见下节：常态改为噪声生成，模板改为后置、用于特殊遭遇。
- **ChunkTemplateLoader**：从 `Resources/chunk_templates` 加载 JSON 模板池。

### 1.4 目标架构（生成优先级：噪声为主，模板后置）

**大体策略**：常态使用文档 **第三节** 的 **噪声 + 世界坐标确定性** 方式填充地形（Perlin / `GetCellData(worldX, worldY, seed)`），与 chunk 边界连贯、可复现。

**模板填充保留，但放到后面、由逻辑触发**：

| 优先级 | 方式 | 说明 |
|--------|------|------|
| 1（主路径） | **噪声程序化生成** | `IChunkGenerator` / `ProceduralChunkGenerator` 按 `seed + chunk 坐标` 生成 `ChunkData`，整 chunk 写入 Tilemap。 |
| 2（有意触发） | **模板填充** | 用于 **特殊地形遭遇**（如固定地牢格、Boss 区、事件房、预置遭遇布局等）：由游戏/关卡逻辑标记「该 chunk（或该区域）需用模板」，再选用对应 JSON 模板填充或局部覆盖；**不是**无差别地对每个 chunk `Random` 抽模板。 |
| 3（兼容/开发） | **`useTemplateFallback` 随机模板** | 保留为未接入生成器、或调试时的回退；正式玩法应以 1 为主、2 为设计好的遭遇，避免与 1 抢默认路径。 |

- 程序化生成器：根据 **种子 + (chunkX, chunkY)** 确定性生成该 chunk 的 `tiles[]`、`blocking[]`、`ground[]`；可与 **第四节** 建筑/结构一样，在生成器内部再按需叠模板（小范围贴图）。
- **特殊遭遇与随机模板的区别**：前者是 **条件满足时选用指定/分类模板**（可配合种子做到可复现）；后者是当前 `GetRandomTemplateCopy()` 的全局随机池行为，仅作回退或过渡期。

## 二、程序化生成器（IChunkGenerator）

### 2.1 职责

- 输入：`seed`、`chunkCoord (cx, cy)`、`chunkWidth`、`chunkHeight`。
- 输出：`TilemapLoader.ChunkData`（含 tiles、blocking、ground、originX、originY、width、height），或 null 表示走回退。
- **纯函数**：相同输入永远产生相同输出，便于同一 chunk 多次加载时一致。

### 2.2 接口定义（示例）

```csharp
public interface IChunkGenerator
{
    TilemapLoader.ChunkData GenerateChunk(
        int seed,
        Vector2Int chunkCoord,
        int chunkWidth,
        int chunkHeight);
}
```

- TilemapManager 在 `LoadChunkInternal` 中：若 `_chunkGenerator != null`，调用 `_chunkGenerator.GenerateChunk(seed, chunk, chunkWidth, chunkHeight)`；非 null 则用返回的 ChunkData。**若实现「特殊地形遭遇」**：在调用生成器之前或根据某 `ChunkOverride` / 事件标记，决定本 chunk **直接使用模板**（指定名或分类），跳过噪声整图；否则仍以噪声为主。未命中任何逻辑且生成器返回 null 时，再走 `useTemplateFallback` + `GetRandomTemplateCopy()`（兼容旧行为）。

### 2.3 种子来源与注入

- **种子**：在游戏/关卡入口生成或传入（如 `Random.Range` 或关卡 ID），存于某全局/单例（如 GameContext）或 TilemapManager 的字段。
- **注入**：TilemapManager 持有可选 `IChunkGenerator _chunkGenerator`，由 Main/LevelManager 在进入游戏时创建并赋值。同一局内种子不变，保证确定性。

## 三、地形生成：噪声 + 规则

### 3.1 思路（2D 适用）

- **俯视角 2D**：每个 tile 的 `(worldX, worldY)` 对应 `cellX = chunkX * chunkWidth + localX`、`cellY = chunkY * chunkHeight + localY`。用 2D 噪声 `noise(cellX * scale, cellY * scale)` 得到 0~1 的值，再映射到 tile id / blocking。
- **横版 2D（平台/侧视）**：通常用 1D 噪声 `noise(cellX * scale)` 作为「高度」，cellY 低于高度为地面（tile+blocking）， above 为空。

### 3.2 噪声函数

- Unity 内置：`Mathf.PerlinNoise(float x, float y)`，2D Perlin，返回值 0~1。可多层叠加、不同 scale/amplitude 做层次感。
- 若需更好质量：可引入 Simplex 噪声（需自行实现或第三方库），或使用 Unity 的 `Noise` API（如有）。
- **确定性**：同一 `(x,y)` 输入，PerlinNoise 输出固定，无需额外种子传入噪声；种子可用于偏移坐标，例如 `noise((cellX + seed) * 0.01f, (cellY + seed * 7) * 0.01f)`，使不同种子产生不同地形。

### 3.3 简单示例：俯视角草地+阻挡

- 对 chunk 内每个 `(localX, localY)`，计算 `worldX = chunkX * chunkWidth + localX`，`worldY = chunkY * chunkHeight + localY`。
- `float n = Mathf.PerlinNoise((worldX + seed) * 0.02f, (worldY + seed * 7) * 0.02f);`
- 规则示例：`n < 0.3` → 空地（tile=0, blocking=0）；`n >= 0.3` → 草地（tile=1, blocking=0）；`n > 0.85` → 石块/墙（tile=2, blocking=1）。具体阈值和 tile id 按项目配置。

### 3.4 横版平台示例

- 高度：`float h = Mathf.PerlinNoise((worldX + seed) * 0.05f, 0) * 5 + baseHeight`，取整得到该列的地面高度。
- 对每个 `(worldX, worldY)`：若 `worldY <= h` 为地面（tile+blocking），否则为空。

## 3.5 地形连贯性：具体设计方案

### 问题

Chunk A 和 Chunk B 相邻。A 的右边界与 B 的左边界是同一排格子。若各自独立随机生成，会出现：

- 类型断层：A 边界是草地，B 边界变成石头
- 变体断层：都是草地，但 A 用草地 A，B 用草地 B，边界突兀
- 边缘瓦片错位：RuleTile 需要知道「邻居是什么」才能选正确贴图，若不知道邻居会选错

### 核心原则：世界坐标即唯一真相

**约定**：对任意格子，其 `(tileId, blocking, groundId)` 只由 `(worldX, worldY)` 和 `seed` 决定，与「属于哪个 chunk」无关。

因此可以定义一个纯函数：

```
GetCellData(worldX, worldY, seed) → (tileId, blocking, groundId)
```

只要这三个参数相同，输出必然相同。Chunk A 生成右边界时、Chunk B 生成左边界时，对同一排世界坐标会调用同一函数，结果自然一致。

### 世界坐标与 chunk 的对应关系

- Chunk 坐标：`(chunkX, chunkY)`，如 (2, 1)
- Chunk 内局部坐标：`(localX, localY)`，范围 0 ~ (chunkWidth-1)，0 ~ (chunkHeight-1)
- 世界坐标（Tilemap 的 cell 坐标）：
  ```
  worldX = chunkX * chunkWidth + localX
  worldY = chunkY * chunkHeight + localY
  ```
- 示例：chunk (2, 1)，chunkSize=32 → 该 chunk 覆盖 worldX 64~95，worldY 32~63

### 单格数据获取函数（伪代码）

```
函数 GetCellData(worldX, worldY, seed):
    // 1. 用世界坐标 + 种子算噪声（不依赖 local 或 chunk）
    scale = 0.02
    n = PerlinNoise((worldX + seed) * scale, (worldY + seed * 7) * scale)  // 0~1

    // 2. 映射到地形类型
    tileId, blocking, groundId = 根据 n 的阈值查表
    例：n<0.3→(0,0,0) 空地; 0.3~0.85→(1,0,1) 草地; >0.85→(2,1,1) 石头

    return (tileId, blocking, groundId)
```

### 瓦片变体（草地 A/B/C）的连贯

若同种地形有多个 tile id（草地 A=1, B=2, C=3），也用世界坐标决定，而非每个 chunk 随机：

```
函数 GetCellData(...):
    n = PerlinNoise(...)  // 主噪声：地形类型
    v = PerlinNoise((worldX+seed2)*0.1, (worldY+seed2*3)*0.1)  // 副噪声：变体
    variant = floor(v * 3) % 3  // 0,1,2
    tileId = baseGrassId + variant
    ...
```

这样相邻格子由连续的噪声决定，视觉上自然过渡。

### 生成一个 Chunk 的完整流程（伪代码）

```
函数 GenerateChunk(seed, chunkX, chunkY, chunkWidth, chunkHeight):
    tiles = 新建数组 [chunkWidth * chunkHeight]
    blocking = 新建数组 [chunkWidth * chunkHeight]
    ground = 新建数组 [chunkWidth * chunkHeight]

    for localY = 0 to chunkHeight-1:
        for localX = 0 to chunkWidth-1:
            worldX = chunkX * chunkWidth + localX
            worldY = chunkY * chunkHeight + localY

            (tileId, blockingVal, groundId) = GetCellData(worldX, worldY, seed)

            idx = localY * chunkWidth + localX
            tiles[idx] = tileId
            blocking[idx] = blockingVal
            ground[idx] = groundId

    return ChunkData(tiles, blocking, ground, originX=chunkX*chunkWidth, originY=chunkY*chunkHeight, ...)
```

关键：**循环内只用 worldX、worldY 调用 GetCellData**，从不使用 localX、localY 参与地形决策。

### 边界为何自然连贯

- Chunk A 的右边界：localX=31，worldX = chunkA_X*32+31，例如 63
- Chunk B 的左边界：localX=0，worldX = chunkB_X*32+0，若 B 在 A 右侧则 chunkB_X = chunkA_X+1，worldX = 64
- 对 worldX=63、64 这两列，GetCellData 用相邻的 worldX 输入，Perlin 噪声连续，输出自然平滑衔接

### RuleTile / 自动铺砖（可选）

若使用 RuleTile，需要根据「上下左右邻居的类型」选贴图。邻居可能在相邻 chunk 内，当前 chunk 生成时该 chunk 可能尚未加载。解决：**不读已加载 chunk，直接对邻居世界坐标调用 GetCellData**：

```
生成 (worldX, worldY) 时：
    typeLeft  = GetTerrainTypeAt(worldX-1, worldY)   // 可能落在左侧 chunk
    typeRight = GetTerrainTypeAt(worldX+1, worldY)
    typeUp    = GetTerrainTypeAt(worldX, worldY+1)
    typeDown  = GetTerrainTypeAt(worldX, worldY-1)
    根据 (typeLeft, typeRight, typeUp, typeDown) 查 RuleTile 表 → 最终 tileId
```

GetTerrainTypeAt 内部与 GetCellData 使用同一套噪声/规则，只是返回类型而非完整数据。这样无需加载相邻 chunk，边界处的边也能正确显示。

### 3.6 主噪声与副噪声

| 噪声 | 作用 | 决定什么 |
|------|------|----------|
| **主噪声** | 地形类型 | 草地 / 石头 / 空地 / 水 … 以及 blocking、能否通行 |
| **副噪声** | 变体选择 | 同一类型下的多种样式（草地 A / B / C） |

流程：主噪声 → 若是草地 → 副噪声 → 草地 A？B？C？主噪声只负责大类，副噪声负责同一类内的视觉变化。

### 3.7 第二格 tile 如何选（具体示例）

- 第一格 worldX=10, worldY=5：`n = PerlinNoise(...)` → 0.6 → 草地
- 第二格 worldX=11, worldY=5：`n = PerlinNoise(...)` → 0.58（输入差 1，输出接近）→ 草地
- 第二格不是「再随机一次」，而是用**自己的世界坐标**算一次噪声，再按同一规则查表。相邻坐标 → 相近噪声 → 相近结果。

### 3.8 Tile 表（TileDatabase）与数据流

- **程序化生成器输出**：tile id（数字 0、1、2…），不是 Tile 资源。
- **TilemapManager 写入时**：用 `tileDatabase.GetTileById(id)` 取出 Tile 库中的 Tile，再 `SetTile`。
- **Tile 表**：普通素材列表即可，每种地形一个 tile，无需特殊「连续」设计。连贯性来自噪声放置逻辑，不是 tile 本身。

最简配置示例：id 0=空，1=草地，2=石头。

### 3.9 多种地形样式的连贯（草地 A/B/C…）

同类型有多个变体时，用**副噪声 + 世界坐标**选变体，不用 Random：

```
n_variant = PerlinNoise((worldX + seed2) * 0.05, (worldY + seed2*3) * 0.05)
variantIndex = (int)(n_variant * numVariants) % numVariants
tileId = grassBaseId + variantIndex
```

副噪声的 scale 调小（如 0.05）可形成「斑块」：一片草地 A、一片草地 B，过渡自然。变体在 Tile 表中按视觉相似度排序，相邻索引更协调。

### 3.10 主噪声与死胡同

- **主噪声不保证连通性**，可能出现孤岛、死路。
- 减少死胡同需额外逻辑：提高空地/草地阈值、出生点安全区、后处理 flood fill 连通等。

### 3.11 连续性为何重要（大类会变时）

- **连续性** = 相邻格子变化平滑、成片，不是每个格子独立随机。
- 有噪声：草地 → 草地 → 石头 → 石头（成片、有过渡）
- 无噪声：草地 → 水 → 草地 → 石头（乱跳、像马赛克）
- 大类可以变，但要**成区域地变**，由噪声控制。

## 四、建筑/结构：噪声决定放置模板

### 4.1 思路

- 地形用噪声生成；**建筑**（树、房子、宝箱等）可用预置 chunk 模板。
- 用另一层噪声或规则判断「该 chunk 或该格是否放置某结构」：例如 `noise2(cx * 0.1f + seed2, cy * 0.1f) > 0.9` 时，该 chunk 中心放一棵树（覆盖部分 tile）。
- 结构可存为小模板（如 3×3、5×5），在生成 chunk 时按规则「贴」到当前 chunk 的某局部区域；或整 chunk 替换为「建筑 chunk」模板（由噪声选哪种建筑）。

### 4.2 与模板系统结合

- 程序化生成器内部可持有 `ChunkTemplateLoader` 引用，需要放建筑时调用 `GetTemplateCopyByCategory("tree", deterministicIndex)` 或类似接口，再与当前噪声生成的地形做混合（如覆盖部分格子）。
- 若暂不实现建筑，可先做纯噪声地形，后续再加。

## 五、TilemapManager 接入

### 5.1 修改点

- 增加可选 `IChunkGenerator _chunkGenerator`。
- 增加 `int _worldSeed`（或从外部注入）。
- **（推荐）特殊遭遇入口**：增加可查询的「本 chunk 是否需模板覆盖」信息来源（例如静态字典、ScriptableObject、或关卡管理器在进遭遇前注册 `chunkCoord → 模板名/模板 id`）。若为特殊遭遇 chunk，则 **直接** `GetTemplateCopyByName(...)` 或等价接口得到 `ChunkData`，**不再**对该 chunk 调用噪声整图生成。
- 在 `LoadChunkInternal` 的 `try` 块中，**逻辑顺序**建议为：
  ```csharp
  TilemapLoader.ChunkData data = null;

  // 1）特殊地形遭遇：优先模板（有意设计好的布局）
  if (TryResolveSpecialEncounterTemplate(chunk, out var tplData))
      data = tplData;

  // 2）常态：噪声程序化生成
  if (data == null && _chunkGenerator != null)
  {
      data = _chunkGenerator.GenerateChunk(_worldSeed, chunk, chunkWidth, chunkHeight);
      if (data != null) { /* 设置 originX/Y 等 */ }
  }

  // 3）兼容：未接入生成器或返回 null 时，随机模板回退（可选关闭）
  if (data == null && useTemplateFallback && _templateLoader != null)
  {
      data = _templateLoader.GetRandomTemplateCopy();
      // ... 设 origin，与现有一致
  }
  ```
  其中 `TryResolveSpecialEncounterTemplate` 为占位名，实现上可与任务/战斗/关卡系统对接；无遭遇时返回 false。

### 5.2 兼容性

- `_chunkGenerator == null` 且无特殊遭遇命中时：行为可与当前一致（依赖 `useTemplateFallback` + `GetRandomTemplateCopy()`）。
- 接入 `_chunkGenerator` 后：**默认走噪声**；模板随机仅作回退或仅用于 **§1.4 表格第 2 行** 的显式遭遇。
- 可支持「部分程序化」：例如仅地表用噪声，主层仍用模板，由生成器内部组合两种数据源。

## 七、实现顺序建议

### 下一阶段：动态地形生成（优先实现）

1. **定义 IChunkGenerator 接口**，实现 `ProceduralChunkGenerator`（**噪声主路径**，与 §3 一致）。
2. **GetCellData(worldX, worldY, seed)**：用 PerlinNoise + 阈值映射到 (tileId, blocking, groundId)。
3. **GenerateChunk**：双层循环，对每个 (localX, localY) 转 world 坐标后调用 GetCellData，填入 ChunkData。
4. **TilemapManager 接入**：增加 `_chunkGenerator`、`_worldSeed`；`LoadChunkInternal` 顺序：**先可解析的特殊遭遇模板**，再噪声生成，最后 `useTemplateFallback`（见 §5.1）。
5. **入口**：游戏启动时生成 seed，创建 ProceduralChunkGenerator 并赋给 TilemapManager。
6. **验证**：同一种子下，同一 chunk 多次进入结果一致；相邻 chunk 边界无断层。

### 后续迭代

- **特殊地形遭遇**：实现 `TryResolveSpecialEncounterTemplate` 与模板按名/按类选取，ChunkTemplateLoader 增加确定性拷贝接口（避免遭遇图也靠全局 Random）。
- 主噪声 + 副噪声，支持多种草地/石头变体。
- 调整 scale、阈值，做出可玩地形。
- （可选）引入建筑：噪声决定是否放置、放置哪类模板。

## 八、可选扩展

- **多生物群系**：用噪声划分区域（草原、沙漠、雪地），不同区域用不同 tile 集与规则。
- **洞穴/地下**：另一层噪声决定某格为「洞」（blocking=0），形成地下空间。
- **存档**：种子持久化，读档后同一坐标生成一致。
- **性能**：若单 chunk 生成较慢，可把生成放在异步任务中，完成后再写 Tilemap（当前 LoadChunkInternal 已是异步，可保持）。

## 九、图集批量导入工具（Editor）

- **菜单**：`Tools / Map / Batch Tiles From Atlas (Sorted)`
- **脚本**：`Assets/Editor/AtlasTileBatchImporter.cs`
- **重复生成**：同一输出目录、同一前缀下 **固定文件名**，覆盖已有 Tile `.asset`（不生成 `_1` 副本）。TileDatabase 默认 **从指定下标覆盖** 连续项；仅首次导入或需接在末尾时再勾选「追加到末尾」。
- **排序**：子 Sprite 按纹理坐标 **先上后下**（`rect.yMin` 降序）、**同行从左到右**（`xMin` 升序），与图集视觉上一致。
- **TileDatabase 顺序**：列表第 0 项 = 图集**最上行最左格**；第 `i` 项对应 `row = i / cols`，`col = i % cols`（`cols = 纹理宽 / 单格宽`）。
- **程序化连续映射**（草地专用图集时）：
  - `cols = 16`，`rows = 16`（1024/64）
  - `atlasIndex = PositiveMod(worldY, rows) * cols + PositiveMod(worldX, cols)`（若 Y 轴与图集上下相反，可对 `worldY` 取反或改用 `rows - 1 - mod`）
  - `tileId = grassBaseId + atlasIndex`（`grassBaseId` 为该图集在 TileDatabase 中**第一个** tile 的 id）
